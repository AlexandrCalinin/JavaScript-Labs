# MyShelf — Личная библиотека книг

Индивидуальный проект по дисциплине **JavaScript**.
Веб-приложение для ведения личной коллекции книг. Написано на чистом JavaScript (Vanilla JS) с использованием возможностей ES6+.

## Автор

- Калинин Александр

## Описание

**MyShelf** — небольшое одностраничное приложение, в котором можно вести свой список книг: добавлять, редактировать, удалять, искать, фильтровать и сортировать их. Также есть возможность импортировать книги из открытого каталога Open Library.

Приложение полностью работает в браузере — данные хранятся в `localStorage`, поэтому ничего не теряется после перезагрузки страницы. Никаких фреймворков и сборщиков не использовалось.

### Возможности

- Список книг в виде карточек (название, автор, обложка, рейтинг, статус, жанр)
- Добавление книги через форму с валидацией всех полей
- Редактирование и удаление книг
- Поиск по названию и автору в реальном времени
- Фильтрация по жанру и статусу прочтения
- Сортировка по названию, автору, году и рейтингу
- Ручная сортировка карточек через **drag and drop**
- Модальное окно с подробной информацией о книге
- Вкладки: «Библиотека», «Добавить книгу», «Поиск онлайн», «Статистика»
- Импорт книг с помощью внешнего API ([Open Library](https://openlibrary.org/dev/docs/api/search))
- Страница со статистикой и диаграммой по жанрам
- Светлая и тёмная темы (сохраняются между сессиями)
- Адаптивная вёрстка для мобильных и планшетов
- Уведомления об успехе и ошибках

## Установка и запуск

Проект не требует установки зависимостей и сборки — это обычный HTML, CSS и JavaScript. Но открывать `index.html` напрямую из файловой системы нельзя, потому что браузер запрещает загрузку ES-модулей и `fetch` через протокол `file://`. Поэтому нужно запустить локальный HTTP-сервер.

### Требования

- Установленный [Node.js](https://nodejs.org/) (любая актуальная LTS-версия).
- Современный браузер (Chrome, Firefox, Edge или Safari последних версий).

### Запуск

В терминале перейдите в папку `individual_work` и запустите простой статический сервер через `npx`:

```bash
cd individual_work
npx serve .
```

После запуска откройте в браузере адрес, который выведет команда (обычно [http://localhost:3000](http://localhost:3000)).

Альтернативный вариант (если `serve` по каким-то причинам не сработал):

```bash
npx http-server . -p 8080 -o
```

Флаг `-o` автоматически откроет страницу в браузере.

## Краткая документация по модулям

### `library.js`

Главный модуль для работы с данными. Хранит массив книг в памяти и предоставляет функции:

- `getAll()` — получить все книги
- `getById(id)` — найти книгу по идентификатору
- `addBook(data)` — добавить новую книгу
- `updateBook(id, data)` — обновить существующую
- `deleteBook(id)` — удалить
- `reorder(fromId, toId)` — переставить (для drag and drop)
- `query({ search, genre, status, sort })` — фильтр + сортировка
- `getStats()` — собрать статистику
- `getGenres()` — список уникальных жанров
- `onChange(fn)` — подписаться на изменения

Любая операция изменения автоматически сохраняет данные в `localStorage` и уведомляет подписчиков.

### `validation.js`

Содержит функции проверки каждого поля формы и общий `validateBook(book)`, который возвращает объект с ошибками (пустой, если всё в порядке).

### `ui.js`

Все функции, которые что-то рисуют на странице: карточка книги, содержимое модального окна, список результатов API, статистика и т. д.

### Остальные модули

- `storage.js` — `loadBooks`, `saveBooks`, `loadTheme`, `saveTheme`.
- `api.js` — `searchBooks(query)` отправляет запрос к Open Library и приводит ответ к нужному формату.
- `modal.js` — `openModal(node)`, `closeModal()`, `initModal()`.
- `tabs.js` — `initTabs(onChange)` возвращает `{ activate }`.
- `dragdrop.js` — `enableDragDrop(container, onDrop)`.
- `toast.js` — `showToast(message, type)`.

## Примеры использования

### Обработка формы добавления книги (`js/main.js`)

```js
function handleSubmit(e) {
    e.preventDefault();
    clearErrors();

    const data = readForm();
    const errors = validateBook(data);

    if (Object.keys(errors).length > 0) {
        for (const field in errors) {
            showFieldError(fieldToInputId[field], errors[field]);
        }
        showToast("Проверьте заполненные поля", "error");
        return;
    }

    library.addBook(data);
    showToast("Книга добавлена!", "success");
    resetForm();
    tabs.activate("library");
}
```

### Фильтрация и сортировка (`js/modules/library.js`)

```js
const result = library.query({
    search: "толкин",
    genre: "Фэнтези",
    status: "want",
    sort: "year-desc"
});
```

### Загрузка данных из внешнего API (`js/modules/api.js`)

```js
const url = URL_BASE + "?q=" + encodeURIComponent(query) + "&limit=12";
const response = await fetch(url);
const data = await response.json();
```

### Сценарии пользования

1. **Добавить книгу.** Открыть вкладку «Добавить книгу», заполнить форму, нажать «Сохранить».
2. **Импортировать книгу из интернета.** Вкладка «Поиск онлайн» → ввести название → нажать «Добавить» рядом с найденной книгой.
3. **Перетащить карточку.** В сортировке выбрать «Вручную», затем перетащить карточку мышью.
4. **Посмотреть статистику.** Вкладка «Статистика» — счётчики и диаграмма жанров.
5. **Переключить тему.** Кнопка с луной / солнцем в правом верхнем углу.

## Ответы на контрольные вопросы

**1. В чём преимущества модульного подхода в JavaScript?**
Модули позволяют разделить код на независимые файлы, каждый из которых отвечает за свою задачу. Это улучшает читаемость, упрощает поддержку и переиспользование. В моём проекте, например, модуль `library.js` не знает ничего про DOM, а `ui.js` — про хранение данных.

**2. Чем `let` и `const` отличаются от `var`?**
`var` имеет функциональную область видимости и поднимается в начало функции (hoisting). `let` и `const` имеют блочную область видимости. `const` дополнительно запрещает переприсваивание ссылки. В проекте `var` не используется.

**3. Зачем нужна валидация на стороне клиента, если она всё равно дублируется на сервере?**
Клиентская валидация даёт мгновенную обратную связь пользователю и не требует обращений к серверу для очевидных ошибок. Серверная валидация нужна для безопасности, потому что клиентскую можно обойти.

**4. Что такое `localStorage` и какие у него ограничения?**
Это хранилище ключ-значение в браузере. Хранит только строки, ограничено объёмом 5–10 МБ, привязано к домену и сохраняется между сессиями. В отличие от `sessionStorage`, не очищается при закрытии вкладки.

**5. Что такое event delegation?**
Это приём, при котором обработчик событий вешается не на каждый дочерний элемент, а на общего родителя. Затем по `event.target` определяется, на чём именно произошло событие. В проекте так сделано в `dragdrop.js` (один слушатель на весь список карточек) и в `ui.js` (одна кнопка `book-actions` слушает клики по всем кнопкам внутри карточки).

**6. Чем отличается `async/await` от `.then()`?**
Это синтаксический сахар над промисами. Код с `async/await` выглядит как обычный последовательный, его проще читать и отлаживать. Под капотом — тот же механизм.

**7. Как защититься от XSS при выводе данных?**
Нельзя вставлять пользовательский ввод через `innerHTML` без экранирования. В проекте я использовал `textContent` для вывода названий, авторов, заметок и других пользовательских данных.
